# Store Interesting Wallet Evidence From Historical Replay

Interesting wallets carry a `chain` attribute (`robinhood` today) so records stay chain-specific, and every reason a wallet is worth watching is a separate `wallet_evidence` event keyed by a deterministic id (kind, chain, pair, wallet). The historical replay `reconstruct` command derives `historical-runner-buy` evidence for pairs manually labelled `runner` straight from the reconstructed Robinhood RPC swap logs, so wallet evidence never depends on live trading data; it keeps only the largest buyers per pair (`--max-wallets`, default 25) and only rewrites evidence on a run that covers the pair's whole requested block range, never on an incremental resume. Manual `wallet_tags` and `pair_tags` (`interesting` or `ignored`) let a human curate the set: tagging a wallet `interesting` adds it, `ignored` removes it and suppresses future derived evidence for that wallet or pair. Wallet evidence, interesting wallets, and manual tags are inspectable through `npm run replay-pairs -- wallets` and the HTML/CSV simulation reports. This extends ADR-0009 and follows ADR-0011's manual-runner replay approach; consuming this evidence in trade-setup ranking is deferred.

# Send Optional Telegram Alerts With Persisted History

The live monitor will send Telegram alerts for new trade setups, simulated fills, stop losses, 2x take profits, repeated data-source failures, and a daily summary for the previous Europe/Paris day. Telegram is an optional adapter configured through `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`; a missing or partial configuration disables only that adapter and never aborts other commands, unless a command opts in with `--require-alerts`. This follows ADR-0004 now that live DEX Screener monitoring is proven. Each delivered alert is recorded in the existing `alert_history` table keyed by a deterministic id, and the dispatcher records only after a successful send, so repeated scans and restarts never resend an alert. A repeated-failure alert fires once per outage, on the scan where an adapter reaches three consecutive failures. Event alerts older than 24 hours are treated as backlog and skipped so enabling alerts on a running monitor does not replay the whole history.
